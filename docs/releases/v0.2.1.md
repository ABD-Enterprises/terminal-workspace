# Terminal Workspace v0.2.1

Patch release focused on **security hardening**: fixed TLS and dependency advisories, added pnpm supply-chain guards, and a notarization step that no longer passes the app-specific password on the command line.

## Install
1. Download **terminal-workspace-macos-v0.2.1.app.dmg** below.
2. Open it and drag **term-snip** into **Applications**.
3. Launch it from Applications. Signed with a Developer ID certificate and notarized by Apple. Apple Silicon (arm64), macOS 13+.

## What changed
- **TLS advisories fixed.** `rustls` 0.23.40 → 0.23.46, with `rustls-webpki` and `webpki-root-certs` on patched versions, clearing seven RustSec advisories including RUSTSEC-2026-0285 (TLS 1.3 handshake messages accepted across encryption level boundaries).
- **Notarization password off argv.** `native:notarize` stores the app-specific Apple ID password into a keychain profile over stdin and authenticates through that profile, so the password never appears on the command line.
- **Private-key import is exclusive-create.** The Node backend writes an imported private key with `O_EXCL`, so a key that appears between the existence check and the write is refused rather than overwritten; `~/.ssh` `Include` matches are read through one file handle, so the size and type checks apply to the bytes actually read.
- **pnpm supply-chain guards.** `pnpm-workspace.yaml` now sets `trustPolicy: no-downgrade`, `blockExoticSubdeps: true` and `minimumReleaseAge: 10080` (7 days). No installed version changes.
- **Dependency advisories cleared.** Dependency bumps for shell-quote (critical) and source-map-js (high), plus browserslist, baseline-browser-mapping, brace-expansion, vite, happy-dom, vitest and zod; `pnpm audit` is now clean in prod and dev. The Rust `glib` advisory does not affect the shipped app — gtk is target-gated to Linux/BSD, so the macOS build never links glib.
- **Signing job without a pnpm store cache.** The macOS release workflow no longer restores or saves one, so the job that signs, notarizes and publishes the app cannot consume a poisoned cache.
